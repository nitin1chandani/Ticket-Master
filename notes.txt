core problems to solve

-Prevent double booking under high concurrency
-Temporary ticket reservation with expiration
-Handle high traffic with caching + async processing

1. Concurrent ticket booking
   → PostgreSQL row locking / transactions

2. Temporary ticket reservation
   → Redis TTL + reservation expiry

3. High traffic
   → Redis caching + Kafka async processing

3. Redis layer

Create something like:

internal/redis/
    client.go
    reservation.go

Responsibilities:

Reserve(ticketID, bookingID, TTL)
Release(ticketID, bookingID)
IsReserved(ticketID, bookingID)

Keep Redis implementation out of your handlers.

4. Booking service

This is where the actual flow lives:

ReserveTickets()
    ↓
Create pending booking
    ↓
Acquire Redis locks
    ↓
Mark tickets reserved in DB
    ↓
Return booking + expiry

Then:

ConfirmBooking()
    ↓
Check Redis reservation
    ↓
DB transaction
    ↓
tickets → sold
booking → confirmed
    ↓
delete Redis locks

5. Background worker

Create:

internal/worker/
    reservation_expiry.go

Every few seconds/minutes:

Find expired reservations
        ↓
tickets → available
booking → expired

This is cleanup, not the primary reservation mechanism.

6. HTTP layer

Endpoints:

POST /events
GET  /events/:id

POST /events/:id/reserve
POST /bookings/:id/confirm

Handlers should be thin:

HTTP Handler
    ↓
Booking Service
    ↓
Repositories + Redis
